Overview

MACD Trader connects to moomoo Securities via OpenAPI to detect MACD Golden Cross (GC) and Dead Cross (DC) signals and automatically trade multiple symbols simultaneously.

Setup

1. Install moomoo OpenD

OpenD is not included in this repository. It must be installed separately from moomoo's official site.

  1. Download OpenD from openapi.moomoo.com (GUI version recommended)
  2. On macOS: if blocked by Gatekeeper, go to System Settings → Privacy & Security → Open Anyway
  3. Launch the app and log in with your moomoo account (SMS verification may be required)
  4. Confirm the status shows "Connected" — port 11111 will now be listening
⚠️
OpenD must be logged in at least once before it can auto-start. start.sh (below) will relaunch OpenD automatically on later runs (e.g. after a Mac mini reboot), but the very first login — including any SMS verification — must be done manually. Your moomoo credentials are entered only in the OpenD app — never store them in any file in this repository.

2. Install Python dependencies

pip install -r requirements.txt

3. Start MACD Trader

Run the included launcher script. It checks whether OpenD is already listening on port 11111 and launches it automatically if not (waiting for it to come up), stops any existing web server, verifies symbols.json exists, and starts the app.

bash /path/to/moomoostock-01/start.sh

# Also auto-start specific symbols' bots after the Web GUI comes up
bash /path/to/moomoostock-01/start.sh --start-bots=US.SPCX,US.CBRS,US.MU

Open http://localhost:5001 in your browser.

To start manually: cd macd_trader && python3 web_app.py

⚠️
Always list symbols explicitly with --start-bots. data/symbols.json can retain configuration for symbols you've deliberately paused (e.g. under re-evaluation) — there's no "all registered symbols" mode, precisely so a reboot can't silently resume monitoring on something you turned off.

Symbol count limit

The moomoo OpenD API enforces the following subscription limit:

symbols × K-line types ≤ 100 (OpenD official spec)

Example: subscribing to K_1M only → up to 100 symbols

⚠️
The theoretical limit is 100, but as the symbol count increases, so does the number of concurrent OpenD connections, which can cause instability. We recommend keeping to 10 symbols or fewer in practice. A warning is shown in the GUI when adding symbols.

4. Configure symbols and start

  1. Copy data/symbols.example.json to data/symbols.json
  2. Click ＋ 銘柄追加 (Add Symbol) in the GUI
  3. Enter a ticker in Futu format: US.NVDA, HK.00700
  4. Keep Paper Trading checked for your first run
  5. Click ▶ 起動 (Start) to begin monitoring

Log Panel

The bottom-right panel aggregates logs from all running bots in real time, polled every second. Only new entries are fetched using an incremental ID. "クリア" clears the display only — log files on disk are unaffected.

Symbol Management

Adding a Symbol

  1. Click ＋ 銘柄追加 (top right)
  2. Enter the ticker in Futu format (US stocks: US.AAPL / HK stocks: HK.00700)
  3. Review settings across all tabs, then click 保存 (Save)
🔍
We recommend screening a symbol before adding it. Use the "🔍 銘柄スクリーニング" button in the header to backtest whether a candidate symbol suits this MACD strategy before committing to it. See Backtest Manual — Symbol Screening for details.

Editing and Deleting

A running bot cannot be edited or deleted. Stop the bot first, then use the 設定 (Settings) or trash icon. Configuration is persisted to data/symbols.json.

Bot Control

Use ▶ 起動 per symbol or 全停止 (Stop All) in the header. Stop requests are async — the bot finishes its current cycle (up to 5 seconds) before halting.

⚠️
Open positions are not closed automatically when a bot stops. Check and manage any open positions manually in the moomoo app.

Post-Market Report

After the trading day ends, run report.py to generate an HTML report evaluating whether each symbol's configured parameter values were actually effective given the day's price action.

cd macd_trader
python3 report.py     # today
python3 report.py 2026-07-25     # a specific date
python3 report.py 2026-07-21_2026-07-24     # a date range (start_end, inclusive)

Output goes to logs/report_<date>.html (private, not tracked by Git). Open it in your browser.

What's in the report

For each symbol:

  • Trade count, win rate, total PnL, average PnL%, average hold time
  • Average GC duration at entry
  • Exit-reason breakdown (take-profit / stop-loss / dead-cross / peak-drop / max-hold-time — count and PnL for each)
  • Comparison against the currently configured thresholds (GC duration, take-profit, stop-loss, peak-drop %, max hold time)

Copy for AI review

Each symbol block has a 🤖 AI評価用にコピー (Copy for AI Review) button, and there's a 🤖 全銘柄まとめてAI評価用にコピー (Copy All Symbols) button at the top. Clicking copies the following to your clipboard as one block of text:

  • The currently configured thresholds
  • Aggregated results (trade count, win rate, PnL, exit-reason breakdown)
  • Raw per-trade data (CSV)
  • A set of evaluation questions (is take-profit/stop-loss actually effective, are entry conditions too strict/loose, concrete parameter change suggestions, etc.)

Paste the copied text directly into a Claude Code chat to get parameter-tuning suggestions.

💡
Why ask an AI instead of building judgment logic into the report? Hard-coding thresholds like "warn if take-profit hit rate is below X%" means the rules themselves need maintenance every time the strategy changes. Handing the raw data to an AI for evaluation each time stays flexible without any code changes.
🧪
To validate parameters against historical data instead of waiting two weeks of Paper Trading, see the Backtest Manual.

Discord Notifications

When running unattended (e.g. a Mac mini left running), you can get a Discord notification the instant a BUY or SELL happens, without needing to keep the web GUI open.

Setup

  1. In Discord, open the channel where you want notifications, go to Integrations → Create Webhook, and copy the Webhook URL
  2. Copy macd_trader/data/notification_config.example.json to notification_config.json in the same folder
  3. Paste your Webhook URL into webhook_url and set enabled to true
  4. Restart the web GUI (not strictly required — the file is re-read on every notification, not only at startup — but restarting guarantees the change is picked up)
{
  "enabled": true,
  "webhook_url": "https://discord.com/api/webhooks/xxxxx/xxxxx"
}

What gets sent

  • On BUY: symbol, quantity, fill price, entry reason
  • On SELL: symbol, quantity, fill price, PnL (USD and %), exit reason
🔒
Security design. The Webhook URL lives only in notification_config.json, which is excluded from Git and never committed. Notification content never includes account numbers, balances, or other account details. Discord webhooks are write-only — they cannot be used to read data back out or as an entry point into the bot or your account. If a notification fails to send, the exception is caught and logged; it never blocks trade execution.

Configuration — MACD

MACD (Moving Average Convergence Divergence) measures trend direction and momentum from two EMAs.

📐
Formulas:
MACD line = EMA(fast_period) − EMA(slow_period)
Signal line = EMA(signal_period) of MACD line
Histogram = MACD line − Signal line

Golden Cross (GC): MACD line crosses Signal line upward → buy signal
Dead Cross (DC): MACD line crosses Signal line downward → sell signal

Pro Strategies: Getting the Most from MACD Trading

Practical guidance from an algorithmic trading perspective

⚠️
This is educational content, not financial advice. Trading carries risk of loss. All decisions are your own responsibility.

MACD is a powerful trend-following indicator, but it is not a magic formula. Using it effectively requires knowing when it works and when it doesn't.

When MACD Works

Strong directional trends, sustained momentum after news or earnings, clear breakouts with volume confirmation, trending markets with price making higher highs.

When MACD Fails

Sideways / range-bound markets (generates repeated false crosses), major macro events (FOMC, CPI — unpredictable spike-and-reverse behavior), low-volume hours. The best action during these conditions is to stop the bots.

Trading Hour Strategy

All times are US Eastern Time (ET).

9:30–10:00 ET
Opening Rush — High Risk
Maximum volume but maximum false signals. Many institutional algorithms are still repositioning. MACD is unreliable here. Watch, don't trade.
10:00–11:30 ET
Prime Trading Window ★
Direction is established, trends are sustained. MACD signals have the highest reliability of the day. Run bots here.
11:30–14:00 ET
Lunch Lull — Stop Recommended
Volume drops sharply. Small orders move prices. MACD generates noise-driven false signals. Stop bots.
14:00–15:30 ET
Afternoon Session — Conditional
Institutional activity resumes. Can work if a clear trend has formed, but news-driven reversals are more common. Trade with caution.
15:30–16:00 ET
Closing — Stop Recommended
Erratic order flow from end-of-day hedging and rebalancing. Avoid new entries; close any open positions. Stop bots.
⏰
Simple rule: Running bots only from 10:00–11:30 ET (and possibly 14:00–15:30 ET) often improves win rate dramatically compared to running all day.

Risk Management in Practice

Position Sizing Formula

Risk per trade = Total capital × daily_loss_pct ÷ max_daily_trades

Correct share count = Risk per trade ÷ (Entry price × stop_loss_pct ÷ 100)

Example: $10,000 capital / 3% daily limit / 10 trades / NVDA @$120 / SL 1.5%
→ Risk per trade = $10,000 × 0.03 ÷ 10 = $30
→ Share count = $30 ÷ ($120 × 0.015) = 16 shares

The 2% Rule

The first rule every professional trader learns: never risk more than 2% of total capital on a single trade. If you lose 10 trades in a row with this rule, 80% of your capital survives. Trade with math, not emotion.

Common Mistakes

❌ Moving the stop loss

"It'll bounce back" is the most dangerous thought in trading. Widening the stop after entry turns small, manageable losses into account-threatening ones. Set the stop before entry and never touch it.

❌ Running too many symbols at once

Monitoring 5+ symbols makes it impossible to understand which signals fire in which conditions. Start with 1–2 symbols and build intuition before scaling up.

❌ Skipping Paper Trading

Switching to live after a few days of paper trading is a common and costly mistake. Accumulate at least 50 trades and 2–4 weeks of data before trading real money. Look for win rate >40% and average win > average loss × 1.5.

❌ Running bots in choppy markets

When the market has no direction (e.g. a sideways day), MACD fires repeated false GC/DC signals. Check pre-market direction and news before enabling bots each morning.

❌ Over-relying on 1-minute charts

1-min charts generate many signals but also enormous noise. Commission costs accumulate quickly. For most users, 5-min charts produce more reliable signals with fewer trades.

Recommended Workflow

The standard process for validating a new algorithmic strategy before committing real capital.

  1. Mock validation (1 day)
    Enable mock_data=true. Confirm GC/DC detection, entry, exit, and logging work correctly.
  2. Paper Trading — 1 symbol, 2 weeks
    Set mock_data=false, paper_trading=true. Run on one liquid symbol (e.g. US.NVDA) at K_5M during market hours.
  3. Analyze the results
    Run python3 report.py and use "🤖 AI評価用にコピー" to have an AI evaluate the configured thresholds. Target: win rate >40%, avg win > avg loss × 1.5.
  4. Adjust parameters
    Find patterns in losing trades (e.g. all during lunch hours). Tighten the GC duration or add a time-of-day restriction.
  5. Go live — minimum size
    Set paper_trading=false with quantity=1. Run for one week to confirm real fills match paper results.
  6. Scale gradually
    Increase position size monthly as confidence grows. Never scale faster than your verified edge justifies.
💼
Final thought: The true value of algorithmic trading is consistent rule execution without emotion. A bot will follow your rules precisely when a human would second-guess them. But if the rules themselves are wrong, the bot executes those mistakes faster and at larger scale.

Prove the rules work in Paper Trading. Then let the bot run them.
